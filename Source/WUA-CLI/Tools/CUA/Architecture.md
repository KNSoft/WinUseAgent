# CUA runtime

One WUA-CLI executable contains the CLI and hidden Workers. Tools/CUA owns inspection, UIA, window operations, input, routing, Worker startup and child sessions. Utils provides capture and general helpers. Run Locate retains its tool entry and shares session routing.

The implementation uses C and MLE/NDK, with UI/COM interfaces where required. MLE provides JSON, IO, command-line conversion and process creation. Capture.cpp retains the Windows SDK ABI for DXGI interop; ChildSession.cpp retains MLE ActiveX and imported RDP interfaces. Neither uses STL or C++/WinRT projections. The manifest declares PerMonitorV2. JSON/capture initialize Ro; flexible callers retry STA after an MTA mode conflict. UIA requires MTA; RPC dispatch accepts an existing STA. OLE/RDP and shell threads require STA. Only successful initialization is balanced.

The CLI reuses Main's parameter parser, resolves Session and OutFile, maps commands with one table and sends each action once. Backend, UIA budgets and deadlines use internal defaults. The Server parses each request once and serializes actions. Public output reuses Main's success/error builders. RPC associates replies with their calls; private JSON carries only method and params.

Omitting Session selects the caller's Windows session and starts its Worker on demand. A numeric Windows session ID selects an existing same-account Worker. Owned child sessions start their Worker after logon. Arbitrary-session logon and Worker startup are not implemented. Preview and Destroy select an owned child by Windows ID and run through its parent Server. An unavailable selection never falls back to the caller's session. Windows currently supports one child; the API uses Windows IDs without relying on that limit. Child management is held by its parent Server; recovery after that parent exits is not implemented.

Handle is a hexadecimal HWND; omitted/zero means desktop where supported. Window input restores and raises the target, then validates focus or hit testing. Click, DoubleClick and Down can use normal mouse activation after hit testing; other physical input requires the actual foreground target. The CLI attempts to transfer its existing foreground permission to the local Worker during the existing readiness probe. Windows may deny activation; no synthetic shortcut, shared input queue or system setting bypass is used. Observations and actions are separate operations; HWNDs and UIA runtime IDs are revalidated at use, but application state can change between calls.

WGC is the default capture implementation; GDI remains a private test option. Window screenshots always include the nonclient area. Without OutFile, inspection measures geometry and returns information without capturing pixels. A requested PNG goes directly to the caller-resolved path. Mouse coordinates and UIA points use the screenshot's upper-left origin; desktop points use the virtual desktop's upper-left origin. Capture and input convert to Windows coordinates internally.

Each Worker owns one persistent, windowless MTA thread, which reuses its UIA objects. It accepts one pending request without a queue. Timeout stops the caller's wait; the thread releases an abandoned request when the provider returns. Inspect reports uia_state=busy while a previous request remains pending; the new UIA request was not queued or executed. uia_state=timeout covers both UIA_E_TIMEOUT and the caller's wait deadline. Capture, input and session management continue. No replacement thread or forced termination is used. A permanently blocked provider leaves UIA unavailable. An Element action may still finish after timeout; inspect before retrying.

Uia.h names the default, connection, transaction and maximum timeouts. Collection keeps text-pattern fallbacks, password redaction, clickable points and node/depth/time limits. Native runtime IDs are returned as comma-separated signed integers for Element operations. UIA geometry and caret hints are converted to screenshot pixels; inconsistent geometry omits pointer coordinates. GetGUIThreadInfo is interpreted after foreground, ownership and sampling checks; background retained focus and native menu/move-loop focus or caret hints are omitted. Text refuses these loops; Keys can finish them. Image, UIA and input context are not sampled atomically.

Resolved input and window operations produce at most one fresh observation. The main API result determines ok; supplemental observation/image errors are attached without changing successful input into failure. API success does not prove the application's intended state changed. On failure or a lost response, callers inspect before continuing because some input may already have occurred.

Text defaults to Message, using WM_UNICHAR when supported or WM_CHAR for a Unicode control. Paste retains the original OleGetClipboard object, publishes temporary Unicode text and sends Ctrl+V. If it still owns the clipboard, it restores the object and flushes before its STA exits. This is best-effort: the object is not an independent snapshot of every format. One GetData call binds OLE's lazy wrapper before replacement; no format backup is stored. A new clipboard owner is left intact. Restoration failure is supplemental to the input result. Calls into an abnormal OLE source may block; retaining the object does not provide a strict deadline.

Local transport uses one ncalrpc Execute interface in the same executable. MIDL generates an asynchronous client and a synchronous Server. Parameters carry bounded UTF-8 requests and replies using MLE JSON; the RPC runtime handles framing. The client waits with a deadline, then cancels and completes an outstanding call before releasing its buffers and binding.

RPC checks the same user SID and requires at least medium integrity. Ordinary and filtered administrator callers can use same-account Workers across Windows sessions. ExpectedSession checks routing; a reported Server PID is process information, not independent authentication. Requests are sent once. After cancellation or a lost response, callers inspect before repeating an operation.

Standard accounts use ordinary startup. Administrator accounts try one hidden UAC launcher, then a same-user token with UIAccess; failures retain available privileges. Child process creation still depends on Windows privileges. A same-executable WMI launcher handles caller job isolation. Once creation is submitted with an unconfirmed outcome, startup does not create another process as fallback.

ChildSession retains its RDP login after Worker startup failure, exit or resolution mismatch. CreateChild waits for login, WTS desktop readiness, Worker startup and graphics readiness, then returns the Windows session ID. Connection has a bounded wait that pauses while the system credential dialog is displayed. Successful login starts a new desktop/Worker startup budget. Only definite ERROR_NO_TOKEN process-creation failures receive at most three attempts; unknown submission is not retried. Confirmed Worker exit allows recovery while retaining login. A live Worker that fails its readiness deadline is retained, not terminated. Credential cancellation, authentication failure and disconnect do not automatically reconnect. CreateChild reuses a retained child with matching resolution and can restart its recovery after the budget is exhausted. Cancelling a CreateChild call stops only that wait and retains the connection, including an active credential prompt. Show applies to initial creation. Preview changes visibility. Destroy or closing it ends the child.

EnableChildSession is an explicit configuration command. CreateChild never changes machine settings automatically. Windows may still require the user to enter a password in its credential prompt. The CLI neither accepts nor saves credentials. Internal Server, SessionLauncher, ConfigureChildSession, TestHost and TestRpc roles and test controls are not public commands.
